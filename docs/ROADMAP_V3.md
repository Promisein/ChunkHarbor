# ChunkHarbor 路线图 V3：R1–R8

冻结日期：2026-11-03。本文是后续计划，不是完成功能声明。现状以源码、实际测试及 [PROGRESS](PROGRESS.md) 顶部为准；起点见[项目审计](PROJECT_AUDIT_2026-11-03.md)。原 M0–M7 定义和记录保留，不改名、不重新初始化工程。

## 范围与质量门槛

- 正确性、数据安全、可恢复性优先于性能；先单用户、再单服务器多用户、最后性能与规模实验。
- 每轮一个可测试最小子任务；已有实现先复用，缺陷先复现再修，不一次交付整阶段。
- 保持 Windows Qt GUI、纯 C++17 protocol/client_core、Linux 自主 LT Reactor 与有界磁盘池边界。Qt socket 只在所属线程使用；网络 loop 和 GUI 线程不运行阻塞磁盘/哈希/SQL。
- 兼容既有协议、持久化会话、历史数据。新 capability、schema 迁移和客户端状态升级先定义兼容矩阵、失败行为及测试；不将新数据库交给旧二进制，不默默重置旧库。
- 不自动删除、改写真实备份数据；生命周期清理先做隔离夹具及只读候选清单，明确保留/引用/在途保护规则，生产删除须有单独授权。
- 无必要不引入依赖。Redis、多 Reactor、双向同步、分布式框架及企业级 SaaS 不属于必交付范围；FastCDC 先作为独立实验。
- 当前仅可信 loopback/SSH 隧道。R5 设计认证时同时落实安全传输；TLS + 认证 + 授权验收前不开放不可信 LAN/公网。SSH 隧道不等于应用用户身份。
- 阶段通过需要代码、平台构建、自动回归和相关真实端到端证据。未验证、注入故障和真实硬件故障分别记录；测试用时不当作性能结果。

## R1：修复现有行为并建立回归基线

**任务**：连接检测状态与实际上传/列表连接状态分离；按可复现证据处理上传异常；明确 full/resume/incremental 与已完成记录、源变化、端点和目标冲突的规则；处理现有 GUI 状态与布局问题。已有重扫修复保留并回归，不重新实现。

**学习重点**：TCP 连接与应用握手不同；Qt 信号顺序和 QObject 线程归属；显式状态机；RAII 与回调寿命；源快照、Exact 基线与幂等提交。

**建议切分**：先只处理顶部连接徽标的语义及回归；再逐个处理证实的上传异常；最后补齐模式切换矩阵。无复现证据的报告先收集步骤，不能当作已确认缺陷。

**验收**：握手成功/拒绝/超时/断开、端点改变、列表独立成功/失败、备份独立成功/失败不会互相伪造状态；重复点击和旧回调不污染新请求。每次修复有失败复现及通过证据；既有 Windows 全量回归和涉及后端时的 Linux 回归通过。full 已有目标保护、resume 源身份绑定、增量 0 块/单块变化不退化。

**当前状态**：R1已完成并于2026-11-03按用户确认关闭。健康检查、已证实上传断连、ComboBox视觉、严格手动模式及后续获授权的auto文件计划均已交付，证据见 [PROGRESS最新验收记录](PROGRESS.md) 和各R1专项。

**本次验收补充**：用户自行验证并确认下拉框无实际故障，明确要求结束R1；原生自动输入专项失败保留为测试记录，不再作为阶段阻塞，也不改写最新CTest实际23/24。约10.9MiB旧截图断连按用户要求停止追查，不将网络波动当作已确认根因。其他未验证平台/故障边界继续如实记录。R2尚未启动，后续需用户另行明确任务；阶段完成不触发自动提交、推送或跨机器同步。

## R2：可靠恢复、历史版本与目录快照

**任务**：复用现有 download_v1，先做 Windows GUI 当前单文件临时下载/校验/发布；新增服务端有界历史查询及指定历史版本读取；定义目录快照清单（逻辑路径→不可变版本 ID），实现文件夹及指定快照恢复。文件夹恢复不是遍历实时分页就假称一致快照。

**学习重点**：不可变版本与 current 指针；分页一致性；快照提交点；FD 固定与 TOCTOU；Windows 路径、重解析点、大小写冲突及原子发布。

**依赖/设计门槛**：R1；先设计历史元数据/时间字段及旧版本兼容，当前 schema v2 的版本对象不等于快照。指定旧版本需新协商语义，不能悄悄改变现有 `--version-id` 当前版本前置条件。快照完成标记只有在所有引用均已提交后才可见；并发源变化、部分成功/中断与空目录策略必须明确。

**验收**：空/中文/多块单文件及多层目录恢复后哈希一致；连续备份 A/B 后分别恢复 A/B；恢复时新版本发布不会混读。中断不发布半文件，重复恢复不覆盖既有目标。拒绝 `..`、绝对/盘符/UNC/设备路径、符号链接/重解析点逃逸及目录替换竞态；Windows 保留名、大小写碰撞、非法字符有明确拒绝/映射规则。快照中断/重启后无伪完成，旧客户端仍可上传/续传/当前版本下载；无效历史 ID、畸形分页和超限响应回归。

## R3：GB 级文件与受限资源下的恢复

**任务**：统一协议、扫描器、快照、GUI/CLI、存储和测试的文件/块数限制；扩展 GB 级上传和下载；有界流式 manifest/plan/文件处理；基础单用户/服务端容量预算、在途预留、超时与故障恢复。R6 再增加按用户分配/管理配额。

**学习重点**：64 位偏移与整数溢出；分页与流式算法；磁盘预留/ENOSPC；超时和取消的所有权；持久确认与重试成本。

**验收**：明确新上限及兼容协商；至少一个实际 ≥1GiB 非稀疏数据集上传/下载后整文件哈希一致，边界 0/块边界/限制值/超限值验证；不得只用稀疏文件冒充真实大文件 I/O。断连、客户端/服务端重启、磁盘/配额不足、超时及取消后可解释恢复；下载是否续传及状态格式须在对应子任务显式定义和验收。测量峰值内存、FD、队列、暂存空间，证明不随文件正文大小线性缓存。空间不足环境标记未验证，不能直接上调常量就宣称完成。

## R4：历史生命周期与长期运行

**任务**：版本/快照保留与回收、孤儿和过期会话处理、SQLite 索引/查询/事务和迁移、日志滚动、可诊断存储清理、启动恢复及长期运行验证。复用当前 WAL/FULL、事务、启动核验与过期处理，不推倒重写。

**学习重点**：引用关系与可达性回收；数据库锁与事务边界；文件系统/SQLite 跨存储崩溃窗口；日志轮转与磁盘预算。

**验收**：先提供只读回收候选，再在专用测试根验证执行；保护 current、保留快照、在途上传/下载引用，重复清理幂等。清理前后/发布中断点注入后重启可恢复，不删除有效版本。查询计划和规模夹具证明索引使用；WAL/日志/临时文件有界策略、事务失败和 busy 行为可复现。迁移前后同数据恢复哈希一致；制定并执行至少 24 小时持续混合操作测试，记录资源趋势和失败，未跑够不能称长期稳定。硬件掉电仍须单独注明。

## R5：单服务器多用户认证与隔离

**任务**：用户认证及安全凭据管理、TLS/受保护传输适配、服务端会话绑定身份、独立存储命名空间、逐操作授权；既有单用户备份归属迁移方案。不采用企业分布式租户系统。

**学习重点**：认证与授权区别；主体/资源/操作；会话 ID 不是访问凭据；非阻塞 TLS 与 Qt 传输适配；SQL 条件和根 FD 的双重隔离。

**验收**：两用户同逻辑路径互不干扰；未认证、认证失败、身份撤销、跨用户猜测 session/version/snapshot ID 对上传/查询/续传/历史/下载均拒绝，无元数据侧漏。证书/主机名验证、机密不落普通配置/日志；旧匿名接口不能绕过授权。旧数据迁移使用复制夹具且失败可诊断，不静默清空或任意划归；默认可信开发策略保留，公网未单独批准前不开放。

## R6：管理员、配额与多用户一致性

**任务**：最小管理员操作、按用户配额与在途预留、安全审计、多用户混合负载下的一致性和公平性。管理操作仅限已定义用户/配额/审计，不扩展为综合运维平台。

**学习重点**：RBAC 最小权限；事务中预留/确认/释放；重复请求幂等；锁顺序；审计可追踪且不记录秘密。

**验收**：普通用户不可管理他人；配额临界并发请求不能超卖，断连/取消/崩溃/重试正确回收预留；管理员变更有权限检查和持久审计。并发同路径更新、混合恢复/清理不丢已确认数据；重复计费/扣额和锁死有回归。资源受限时错误明确，一个慢用户不会无界占用全局队列。

## R7：有界并行与独立算法实验

**任务**：按证据实现有界多文件并行，分析 SQLite 串行点、锁竞争、哈希和磁盘瓶颈；独立实现/评估 FastCDC 内容定义分块与跨偏移数据复用。不能先换存储协议再找实验理由。

**学习重点**：生产者/消费者、背压、全局与每任务预算、SQLite 单写者、Amdahl 定律；CDC 边界、强哈希二次校验及索引成本。

**验收**：串行与多个有界并发档使用相同数据/持久性标准对照；上传/取消/失败/关窗后无悬空回调和资源泄漏，重启后状态正确。记录吞吐、CPU、RSS、FD、队列、磁盘、SQL 等待；提升或退化均保留。FastCDC 对照固定块：未变/同位置修改/头部插入/偏移/随机数据，核验重建哈希、传输量、CPU、内存及索引占用；记录算法参数、依赖/许可证。负结果有效，不强制合入生产。

## R8：压测、故障矩阵与可复现报告

**任务**：独立压测客户端，Docker 模拟多连接/隔离网络，弱网、慢端、故障场景；条件允许开展云服务器验证。Docker 仅为实验基础设施，不意味着产品变成分布式系统。

**学习重点**：负载模型、百分位与错误率、瓶颈归因、容器资源限制、网络故障与可靠性区别。

**验收**：记录提交 SHA、编译选项、硬件/内核/磁盘、容器限制、网络拓扑、SSH/TLS 开销、数据集生成种子及命令。多轮报告吞吐、P50/P95/P99、错误率、CPU/RSS/FD/磁盘/队列及恢复时间；区分缓存冷暖与逻辑/实际网络字节。弱网/断连/进程崩溃后逐项校验数据和会话，实验结束还原网络设置。保留原始结果和失败；公网需 R5/R6 安全验收、部署/证书/防火墙及用户授权，条件缺失则标记未执行，允许先交付本地完整报告。

## 每轮学习、实现、测试与记录

1. 读 AGENTS、开发指南、本路线图、PROGRESS 顶部；查 Git 状态/提交/相关源码和测试。跨机器先对 SHA/工作区，不自动 pull/reset/stash/同步或 push。
2. 选一个 R 子任务，说明现有能力、具体复现/行为目标、涉及文件/接口、线程与资源归属、失败路径、兼容/数据迁移影响和测试平台。
3. 先解释本轮知识点。功能/缺陷轮添加能验证行为的测试，缺陷先复现，再最小修改；文档轮只核对事实和链接，不自动转业务开发。
4. 对应平台配置/构建/CTest及相关真实集成；Qt 状态测试、Linux 故障注入、SSH 联调按影响选择。完成必要检查后不无理由重复扩测。自动测试只操作自建临时根，不指向真实备份。
5. PROGRESS 顶部记录日期、基准 SHA、已完成/进行中/规划中/未验证、精确命令/退出结果/数量、失败和原因、兼容性及数据风险、下一项唯一最小任务。历史记录保留，专项验收文档链接原始证据。
6. 中文交付功能/文档变化、关键取舍、真实测试、未执行原因、风险和下一步；不自动提交/推送，不以类声明、静态审查或历史测试冒充本轮验证。
