# M6 Windows GUI 服务端文件列表

本轮将文件页从本机提交历史切换到真实服务端分页；版本历史页继续显示本机历史。只做列表，不实现GUI下载或历史快照。

## 实施范围与接口

- ServerFilesModel继承QAbstractTableModel，仅持有当前一页（最多32条），显示逻辑路径、精确字节数、版本和SHA-256；不伪造本地路径或提交时间。
- FileListController拥有模型及独立QtTcpTransport；使用现有file_list_v1协议。异步QTcpSocket与小型控制报文处理均在所属Qt事件线程，无阻塞waitFor或磁盘扫描。每页重新连接并协商，每次仅一个在途请求，下一页由用户触发。
- QtTcpTransport增加显式请求模式：能力协商、递增request_id、一次请求/响应、5秒握手和10秒响应超时、64KiB接收上限。原连接检测模式与七类握手测试保持兼容，不改变顶部连接检测状态含义。
- 控制器检查页内/跨游标排序、响应条目数、请求关联和下一游标，成功才替换整页。失败保留当前页并标记“上次结果”；不显示为最新查询成功。
- 刷新回到第一页，上一页/下一页基于路径游标。历史游标最多128个（约512KiB），不累计文件全集；当前页搜索明确仅筛选已加载页。分页为实时视图，不保证跨页快照或总数。
- 取消/端点变更中止连接；端点变更清空模型和翻页历史，旧回调不能更新新端点。关闭窗口直接销毁QObject/socket/timer，无额外线程等待。
- 界面提供刷新、翻页、取消、查询状态、只读详情与禁用的恢复按钮；本机历史仍在版本历史页。服务端文本只按纯文本显示，64位大小不经过double。

2. 添加模型、控制器、传输请求模式和页面组装；不改Linux服务端及共享协议格式。
3. Windows真实Qt窗口/控制器对loopback测试peer验证分页/筛选/精度/错误/取消/端点切换/关窗/超时，并保留旧GUI回归。
4. 经SSH连接专用Ubuntu测试根真实分页；使用已完成的M6服务端，不替换Ubuntu主工程或接触用户备份数据。
5. 更新PROGRESS、GUI设计与真实验收记录；不自动提交/推送。
