# M5 GUI Implementation Plan

**Goal:** 将现有中文Widgets原型接入真实目录预览、固定块备份和持久续传，完成M5验收。
**Architecture:** GUI线程的TransferController拥有任务模型和本地记录；后台worker复用client_core同步驱动，后台线程独占自己的QTcpSocket和文件句柄。queued信号回传有界、节流的进度。保留现有QtTcpTransport作为异步连接探测。
**Tech Stack:** C++17、Qt6 Widgets/Network、现有protocol/client_core。
**Spec:** 根目录CODEX_DEVELOPMENT_GUIDE.md M5及用户批准的GUI完成度审查。

## Constraints and rulings

- 用户已批准直接完成全部M5，不再次等待设计确认。继续既有中文视觉；不实现M6下载协议或M7认证。
- 当前未提交UI是前轮成果，保留在原目录供CLion直接运行；新建codex/m5-gui分支隔离提交，不移动、丢弃或自动提交用户修改，不推送。
- Files/Versions展示本客户端真实提交记录，明确不代表全服务器文件目录；恢复禁用。服务端全量分页浏览属M6。
- 文件最大64MiB、端口只连接loopback/SSH；无浮点JSON整数；源文件/端点/模式/基线绑定；预览执行前复核。
- full模式为首次完整备份（已有目标拒绝）；incremental复用旧块；resume保留源身份与服务端checkpoint，仅补缺失块。
- 暂停在安全请求边界生效，可能存在一个进行中请求；取消保留已确认进度，重试恢复；关闭窗口协作取消后台任务。
