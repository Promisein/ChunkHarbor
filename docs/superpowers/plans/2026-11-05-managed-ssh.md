# SSH 隧道自动管理实施计划

目标：Windows GUI 日常启动、连接和退出不依赖手工终端；保留直接 TCP、既有 HELLO、业务任务和检查点。

架构：SshTunnelManager 在 GUI 线程异步管理一个 QProcess、就绪/超时/退避定时器，复用 QtTcpTransport 健康探测。Windows 使用端口 PID 归属验证，拒绝外部监听器；所有业务仍使用原有协议和独立 socket。配置变化与关闭走现有失效及任务收尾流程。

边界：不改服务端、协议、SQLite、上传/恢复算法；不写 SSH 配置、密码、私钥；不自动提交或推送。

- [x] 测试先复现旧设置缺少自动 SSH 配置，再实现可测试的组件及受控子进程替身。
- [x] 设置持久化、启动/重试/主动断开、顶栏状态、业务可用性与异步关窗接入；外部测试转发夹具明确使用 TCP，不降低原断言。
- [x] 独立临时服务根真实 Windows OpenSSH 自动连接、HELLO、服务未启动、重连、上传/下载和关闭清理验证；Windows 构建完整 CTest、Ubuntu 既有 CTest。
- [x] 只读审查，修复发现的问题；更新 PROGRESS、R2.6 使用与专项交付文档，记录未验证项。

重点：QProcess 启动不等于监听成功，监听不等于 HELLO；端口竞争不能误信外部进程；旧进程 finished 不能影响新配置；关闭先完成文件操作；重连不重跑任务；认证与主机密钥错误须立即提示一次性配置。
