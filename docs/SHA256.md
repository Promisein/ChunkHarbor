# SHA-256 工具（M2 独立子任务）

`chunkharbor_hash` 是独立的可移植 C++17 target，仅私有链接 `OpenSSL::Crypto`。
`protocol`、`client_core` 和 Reactor 的依赖保持原样；本轮未实现上传或存储。
Linux 默认启用 `CHUNKHARBOR_BUILD_HASH`，Windows 默认关闭以保留无需 OpenSSL 的协议测试；Windows 可显式打开。

## 接口与所有权

公共头：`include/chunkharbor/common/Sha256.h`，命名空间 `chunkharbor`。

- `Sha256Digest`：32 字节 `std::array<uint8_t, 32>`，可直接用于后续二进制块摘要。
- `sha256(string_view)`：计算一个内存块的摘要，包含 NUL 字节，不复制输入。
- `Sha256::update` / `finish`：同一个逻辑字节流可分段输入；finish 后不可更新或再次完成，抛 `logic_error`。独立块应使用独立实例，不能把各块摘要拼起来当作整文件摘要。
- `sha256Stream(istream&)`：从当前位置读到 EOF，使用固定 64 KiB 缓冲；支持 failbit/badbit 异常掩码。初始错误状态、打开/读取失败均拒绝返回摘要。
- `sha256File(filesystem::path)`：二进制模式打开文件并流式计算，不写入源文件。Windows 使用原生 filesystem 路径，与协议逻辑路径分离。
- `toHex`：输出精确 64 字符小写十六进制字符串。

PImpl 隐藏 OpenSSL 类型；`unique_ptr` 与自定义释放函数管理 EVP 上下文，构造失败和异常退出也会释放。禁止复制和移动上下文；同一实例由一个线程使用。所有 Init/Update/Final 返回值均检查，失败后不会继续使用上下文。使用 EVP 高层 API 而非旧的低层 SHA256_CTX；接口约束参考 [OpenSSL EVP 文档](https://docs.openssl.org/3.0/man3/EVP_DigestInit/)。

N 字节输入的计算时间为 O(N)，额外内存 O(1)；文件读取缓冲固定 64 KiB，不随文件大小增长。`string_view` 是借用，调用期间输入必须有效；投递 DiskExecutor 时应捕获拥有数据的对象，不能捕获即将失效的视图。文件哈希是阻塞任务，调用方应放入 DiskExecutor 工作函数；完成回调只取摘要/异常并推进状态。本轮尚未接入上传业务。

## 验证与调试

普通 Ubuntu 安装 `libssl-dev` 后使用 README 的 CMake 命令即可；单独测试和调试：

```bash
cd /home/ning/ChunkHarbor
cmake --build build -j 2
ctest --test-dir build -R '^sha256_test$' -V
gdb --args ./build/chunkharbor-sha256-test
# break chunkharbor::Sha256::update
# break chunkharbor::Sha256::finish
# run
```

测试包括空输入、abc、NIST 长消息、百万个 a 的固定已知摘要；0..255 二进制数据、分段更新、重复结束拒绝、64 KiB 前/中/后边界、流当前位置、流异常掩码、首次/读取64KiB后注入错误和不存在文件。边界摘要由独立 .NET SHA256 生成并硬编码，避免只用工具自身作为期望值。文件测试使用中文文件名，在独占临时目录内运行，退出时仅清理该测试目录。

本轮 Ubuntu 无 sudo 免密权限且缺开发头，采用匹配系统 OpenSSL 3.0.2 的 Ubuntu 包在忽略的构建目录内解压，仅供验证。精确命令：

```bash
mkdir -p build/deps
cd build/deps
apt-get download libssl-dev=3.0.2-0ubuntu1
dpkg-deb -x libssl-dev_3.0.2-0ubuntu1_amd64.deb openssl
cd ../..
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DCHUNKHARBOR_BUILD_HASH=ON \
  -DOPENSSL_INCLUDE_DIR=/home/ning/ChunkHarbor/build/deps/openssl/usr/include \
  -DOPENSSL_CRYPTO_LIBRARY=/usr/lib/x86_64-linux-gnu/libcrypto.so.3 \
  -DCMAKE_CXX_FLAGS=-I/home/ning/ChunkHarbor/build/deps/openssl/usr/include/x86_64-linux-gnu
cmake --build build -j 2
ctest --test-dir build --output-on-failure
```

ASan/UBSan 使用同一配置，将 `-B build` 改为 `-B build-asan` 并加 `-DCHUNKHARBOR_SANITIZERS=ON`；构建后执行：

```bash
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1 \
  ctest --test-dir build-asan --output-on-failure
```

Windows 本轮使用 MinGW 13.2 及本机 MinGW SDK 的 OpenSSL 1.1.1k 兼容性验证（不是生产依赖版本建议）：

## 边界

文件哈希不提供文件系统快照或防止并发修改；结果仅对应实际读取到的字节，不保证期间源文件未变。后续上传须另做文件身份、大小和修改状态检查。路径入口不负责服务端根目录隔离或防符号链接逃逸，不能直接把不可信协议路径传入；安全打开文件和路径约束属于后续存储层。流接口可承接安全打开后的适配流。

读取为同步操作，没有超时/取消；调用方须提供有限且能完成读取的普通文件/输入，不能把 FIFO 等可能无限阻塞的输入提交为退出时必须排空的磁盘任务。未注入 EVP 提供者错误或 OOM，未运行本轮 Release/TSan，也没有性能基准。
